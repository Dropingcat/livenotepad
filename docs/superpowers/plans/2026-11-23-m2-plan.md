1. Все тех-карты блока (ниже) имеют APPROVE ревьюера и аудитора.

4. Выполнен шаг деплоя: снапшот проекта в `.runs\M2\snapshot\`, запись в журнал.
5. Пункты `PROGRESS.md` (M2) и аудитные пункты AUD-001…007 закрыты с доказательством.

- Сложность: средняя–высокая.
- Интерфейсы:

- Валидация (errors): не объект/массив; нет известных секций (`logs` — алиас `training_log`); секция не массив; `notes[]` без `id`, `id` не непустая строка, дубль `id`, пустой `text`, `createdAt` не конечное число, `completedAt/reopenedAt/dueAt/deletedAt` не `null|число`, `branchConfidence` присутствует и не число (**F1**: строка роняет `toFixed`); `word_evidence[]` без `stem`/`branch`, `branch` не строка (`branch:''` валиден, `null` → `DataError`), `evidence`/`distinctNotes` не числа; `word_meta[]` без `stem`; `training_log[]` не объект или `id` не целое `>=0`.

- Поток: parse → `validateImport` → при `errors.length` toast с безопасным сообщением (`err?.message || err?.name`) + `return` без касания БД → сводка/подтверждение warnings → `DB.mergeAll` одной транзакцией → `loadNotes`/`render`/`renderTab` → событие `IMPORT`.
- Слияние заметок: upsert по `id`; заметки, которых нет в файле, остаются.
- Слияние обучения (§7.6): `evidence=max`, `distinctNotes=max`, `lastSeenAt=max`; строки по `['stem','branch']`; `state`/`distinctNotes` meta пересчитываются `recomputeMeta`; `userCurated` — логическое ИЛИ; `branch:''` — обычный ключ.
- Атомарность: одна `readwrite`-транзакция; синхронный цикл без `await`; `try/catch` + **синхронный** `tx.abort()`; `promTx` реджектит `tx.error || req.error || new Error(...)`, не `null` (**F2**); `count` последним, `0` — валидный результат (**F3**/N-14); исходные `id` логов сохранять, если целое `>=0`.

- Тесты: 16 кейсов валидации + 11 кейсов слияния §7.6 + негативные атомарности (sync `DataError`/`DataCloneError` → abort; `{notes:[]}` → resolve 0; лог с `id` → id сохранён).
- Проверки: `npm test`; `node --check` извлечённого модуля по маркерам `<script type="module">…</script>`, не по номерам строк; браузер: битый файл не меняет счётчик заметок, частичный импорт не удаляет, повторный импорт не меняет counts.

### M2-AUD-002b — Экспорт формат 4
- Цель: полный и частичный экспорт с манифестом, счётчиками и checksum; журнал фиксирует `EXPORT`.
- Файлы: `www/js/export-format.js` (`buildExport`, `canonicalJson`, `checksum`), `test/export-format.test.js`, `www/index.html` (`DB.getSnapshot`, `exportAll`, `exportNotes`, `exportLearning`, `exportLogs`, адаптер импорта).
- DoD: `buildExport` → `{format, formatVersion:4, schemaVersion:4, appVersion, exportedAt, exportId, mode, sections, counts, checksum, tuning, data}`; `sections` — карта присутствия (boolean), `counts` — длины; полный — 4 секции; частичный — только присутствующие + `mode:'partial'`; `DB.getSnapshot()` читает 4 store в одной readonly-транзакции (без torn snapshot); `exportLogs` пишет `training_log`; импорт принимает legacy `logs` и старый верхнеуровневый формат; `IMPORT` пишет `fileHash`; событие `EXPORT`.
- Решения по Q1–Q9 (ресерчер AUD-002a):
  - **checksum:** `canonicalJson` — code-unit сортировка ключей, массивы как есть, `undefined` drop, `NaN`/`Infinity` reject, `-0→0`, без Unicode `normalize`; SHA-256 по UTF-8, `'sha256:'+lowercase hex`; хэш **только `data`**; известные векторы `d3626ac3…` и `0abaac6f…`.
  - **инварианты:** `counts[key] === data[key].length`, `mode:'full'` ⇔ ровно 4 секции, `sections` ⇔ ключи `data`; расхождение — error.
  - **checksum-политика:** отсутствие — warning; несовпадение — error до записи; recovery — «импорт без проверки, только merge» или удаление `checksum`; replace с mismatch запрещён.
  - **LAN HTTP:** `crypto.subtle`/`randomUUID` отсутствуют; добавить чистый JS SHA-256 fallback (без зависимостей), чтобы экспорт с телефона по LAN тоже имел checksum; `getRandomValues` доступен.
  - **версии:** `CURRENT_SCHEMA_VERSION=4`, принимать 3/4, `formatVersion` валидировать отдельно, `note.schemaVersion` не трогать; тест-матрица 12 клеток.
  - **`sections`/`counts`:** `sections` — boolean-карта, `counts` — длины; внутренний `validateImport.sections` переименовать в `content`, чтобы не путать с манифестом.
  - **`logs`:** только `training_log`, не дублировать; legacy `logs` принимать; релиз-нота о несовместимости вниз (F-1: старая сборка на формате 4 стирает базу).
  - **replace:** в 002b не реализуется; только 002d, `mode:'full'` + backup + guard в UI и в пайплайне.
  - **скачивание:** `revokeObjectURL` через `setTimeout(...,0)`; гейт — перехват `createObjectURL`/`anchor.click` как основной + `Browser.setDownloadBehavior` дополнительно; `stepCount/passCount/appHash`.
  - **`IMPORT`:** `fileHash` = SHA-256 байтов файла + `exportId` из манифеста.
- Проверки: `npm test`; браузер: скачивание полного и частичного файла, JSON валиден, `checksum` совпадает; импорт старого файла работает.

### M2-AUD-003 — Ввод теряется при Enter во время сохранения
- Цель: два Enter подряд с разными текстами дают две заметки; ни один отправленный текст не пропадает.
- Причина: обработчик `keydown` (около 836) делает `await addNote(text)` и только потом очищает поле. Второй Enter во время `await` вызывает `addNote`, который выходит по `state.adding`, после чего обработчик очищает поле — новый текст теряется.
- Файлы: `www/index.html` (`addNote`, обработчик `keydown` в `draft`), новый `www/js/add-queue.js` (серийная очередь), `test/add-queue.test.js`.
- Сложность: низкая–средняя.
- Интерфейс: `createSerialQueue(task)` → `enqueue(arg)`; каждый вызов ставится в цепочку, следующий стартует только после завершения предыдущего; отклонённая задача не рвёт цепочку; `enqueue` возвращает промис конкретной задачи.
- DoD: по Enter текст фиксируется и поле очищается сразу (текст уже «взят» очередью); сохранения идут строго последовательно; второй Enter во время сохранения не теряется; повтор того же текста в окне 2 с по-прежнему отсекается `isDuplicateAdd`; при ошибке сохранения текст возвращается в поле, если поле пустое, и показывается toast.
- Тесты (`test/add-queue.test.js`): порядок выполнения двух задач; вторая не стартует до завершения первой; reject первой не блокирует вторую; аргументы передаются без искажений.
- Проверки: `npm test`; браузер: «A» Enter → сразу «B» Enter → две заметки A и B; тот же текст дважды за 2 с → одна заметка; ошибка сохранения (эмуляция) → текст вернулся в поле.
- Зависимости: нет (но файл общий с AUD-002 → строго последовательно).

## Правила работы кодера (по 15 и 09)

- Кодер (`general`) получает одну карту за раз, контракт из 15 §2, текст DoD и список файлов.
- Если в карте возникает сложность, кодер фиксирует неопределённость, при возможности продолжает другие карты, не зависящие от неё, и возвращает список неопределённостей.
- Если продолжить нельзя, кодер останавливается и возвращает неопределённости мне.
- Я диспатчу аналитика (`general` по контракту 08) или запрашиваю решение у пользователя. После этого перепланирую и выпускаю новую тех-карту.
