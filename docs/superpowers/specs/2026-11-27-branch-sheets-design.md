## 1. Цель

Одна база заметок. Когда ветка разрастается, её заметки **показываются** на отдельном листе. Лист — это фильтр над той же базой, а не копия, не перенос и не новая таблица. Главный лист остаётся «входящим»: на нём всё, что не разложено по разросшимся веткам.

Пользователь листает листы нижней полоской, а не свайпом по заметкам. Жесты заметки (UX-001) не меняются: свайп влево — выполнено, удаление — только из меню по long-press, ЛКМ — выполнено, ПКМ — меню, протяжка мышью — ничего.

## 2. Не-цели

- Не менять классификацию веток, обучение, `noteIds`, decay, импорт/экспорт.
- Не добавлять новые stores IndexedDB и не поднимать версию БД. Схема остаётся v3.
- Не делать ручное создание/переименование/удаление листов, вложенность, drag-and-drop.
- Не персистить активный лист между перезагрузками.
- Не анимировать смену листа горизонтальным слайдом.
- Не трогать extension в рамках основного M8; sidebar — отдельная опциональная карта SHT-005.
- Не исправлять TD-DEV-18 (меню у просроченных) — вне scope.

## 3. Термины и инварианты

| Термин | Значение |
|---|---|
| **Лист** | Представление (фильтр) над `state.notes`. Не хранит данные. |
| **Главный лист** | `key = null`. Показывает всё, кроме разросшихся веток. |
| **Лист ветки** | `key = branch` (`rabota`, `byt`, `ljudi`, `zdorovie`, `ucheba`). |
| **Разросшаяся ветка** | Ветка, у которой больше `SHEET_OVERFLOW_THRESHOLD` активных заметок. |
| **Активная заметка** | `!note.deletedAt && note.completedAt == null`. |

Инварианты:

1. Данные не дублируются: каждая заметка существует в `notes` ровно один раз.
2. Каждая активная заметка отображается ровно на одном листе.
3. Сумма `count` всех листов равна числу активных заметок.
4. Выполненные и удалённые заметки не создают лист и не удерживают его.
5. Исчезновение листа — это снятие фильтра, а не слияние или потеря данных.
6. Главный лист — всегда первый; листы веток идут в порядке `BRANCH_KEYS`.

## 4. Порог и состав листов

Новый параметр в `www/js/constants.js`:

```js
export const TUNING = Object.freeze({
  // ...
  SHEET_OVERFLOW_THRESHOLD: 5
});
```

Правило: лист ветки появляется при **6+ активных** заметках и исчезает при **5 и меньше**. Выполненные и удалённые не считаются.

### 4.1. Чистый модуль `www/js/sheets.js`

```js
export const SHEET_MAIN = null;

export function isActiveNote(note) { /* !deletedAt && completedAt == null */ }

export function countActiveByBranch(notes) { /* Map<branchKey, number> */ }

export function sheetTitle(key) { /* null → 'Все'; branch → 'Работа' и т.п. */ }

export function computeSheets(notes, threshold = TUNING.SHEET_OVERFLOW_THRESHOLD) {
  // → [{ key: null, title: 'Все', count }, { key: 'rabota', title: 'Работа', count }, ...]
}

export function overflowKeys(sheets) { /* string[] — keys без главного */ }

export function isOnSheet(note, sheetKey, overflow) { /* overflow: Set<string> */ }

export function filterBySheet(notes, sheetKey, overflow) { /* notes[] */ }

export function resolveActiveSheet(sheets, activeKey) { /* key | null */ }

export function shiftSheet(sheets, activeKey, delta) { /* key | null, с клампом */ }
```

`computeSheets`:

1. Считает активные заметки по каждой ветке из `BRANCH_KEYS`.
2. `overflow` — ветки с `count > threshold`, в порядке `BRANCH_KEYS` (не по количеству).
3. `count` главного — активные заметки с `branch == null`, неизвестной веткой или веткой не из `overflow`.
4. Возвращает `[main, ...overflow]`. Если разросшихся веток нет — массив из одного главного листа.

`isOnSheet`:

- главный: `note.branch == null || !overflow.has(note.branch)`;
- лист ветки: `note.branch === sheetKey`.

`resolveActiveSheet`: если `activeKey` есть среди листов — вернуть его; иначе `null` (главный).

`shiftSheet`: индекс активного листа + `delta`, кламп в `[0, sheets.length - 1]`, вернуть ключ. Без зацикливания.

### 4.2. Примеры

| Состояние | Листы |
|---|---|
| 5 «работа», 5 «быт» | только главный (10) |
| 6 «работа» | главный + «Работа · 6» |
| 6 «работа», 6 «учёба» | главный + «Работа · 6» + «Учёба · 6» |
| 6 «работа», одну выполнили | только главный (10) |
| 6 «работа», одну удалили | только главный (10) |
| 6 заметок без ветки | только главный |
| 6 заметок с неизвестной веткой | только главный |

## 5. Что показывает каждый лист

| Блок | Главный лист | Лист ветки |
|---|---|---|
| Активные заметки | все, кроме разросшихся веток | только эта ветка |
| «Просрочено» | **глобально**, включая разросшиеся ветки (осознанное исключение) | только эта ветка |
| Дайджест | да, только здесь | нет |
| «Сделано сегодня» | только заметки главного | только этой ветки |
| «Корзина» | только заметки главного | только этой ветки |
| Пустое состояние | специальное, если всё на листах | «На этом листе пусто» |

Детали:

- Сортировка не меняется: просроченные → срок → `createdAt` desc; выполненные — `completedAt` desc.
- Глобальное «Просрочено» на главном может дублировать просроченные с листа ветки. Это дублирование **представления**, не данных (TD-DEV-23).
- Если лист ветки исчезает, её выполненные и удалённые заметки автоматически возвращаются на главный — фильтр снят.
- Дайджест на главном строится из глобальных просроченных + `DUE_TODAY` главного. На листе ветки блок не рендерится.
- Счётчики на полоске — только активные заметки.

## 6. Нижняя полоска листов

### 6.1. Разметка

Внутри `#app`, после `#list`, перед `footer`:

```html
<nav class="sheet-bar" id="sheetBar" aria-label="Листы" hidden>
  <button class="sheet-arrow" id="sheetPrev" type="button" aria-label="Предыдущий лист">‹</button>
  <div class="sheet-dots" id="sheetDots"></div>
  <div class="sheet-title" id="sheetTitle" aria-live="polite"></div>
  <button class="sheet-arrow" id="sheetNext" type="button" aria-label="Следующий лист">›</button>
</nav>
```

Пример: `‹ ● ○ ○ Работа · 7 ›`.

### 6.2. Поведение

- Высота 44 px, `flex-shrink: 0`, `border-top: 1px solid var(--line)`.
- Показывается только если листов больше одного. Иначе `hidden` и не занимает место.
- Заголовок: главный — `Все · N`, ветка — `Работа · N`, где `N` — активные.
- Точки: по одной на лист; главная — первая. Активная залита цветом ветки (главная — `var(--accent)`), у неактивной только контур.
- Стрелки: `‹` / `›`, на краях `disabled`, без зацикливания.
- Тап по точке — прямой переход. Тап по стрелке — ±1.
- Заголовок с `text-overflow: ellipsis`; на 320 px допустимо `Раб…`, точки и стрелки остаются рабочими.
- Тёмная тема — на существующих CSS-переменных.
- Монитор перекрывает полоску (z-index 400), специальных действий не нужно.

## 7. Жесты и клавиатура

### 7.1. Разрешение конфликта (TD-DEV-22)

Горизонтальные жесты переключения листов живут **только на нижней полоске**. Список заметок и сами заметки не участвуют. Это сохраняет UX-001 без арбитража «свайп по заметке — это выполнение или листание?».

### 7.2. Чистый решатель

В `www/js/gestures.js`:

```js
export const GESTURE = Object.freeze({
  // ...
  SHEET_SWIPE_MIN: 40
});

export function resolveSheetSwipe({ dx = 0, dy = 0 } = {}) {
  // |dx| >= 40 и |dx| > |dy|: dx < 0 → 'next', dx > 0 → 'prev'
  // иначе → 'none'
}
```

Граница: ровно 40 px считается свайпом. Равная диагональ — `none`.

### 7.3. Полоска

- Pointer Events (`pointerdown` / `pointermove` / `pointerup` / `pointercancel`), `setPointerCapture`.
- `pointerdown` запоминает точку; `pointerup` вызывает `resolveSheetSwipe`.
- Если сработал свайп — переключить лист и подавить следующий `click` на 150 мс (чтобы протяжка с точки не сработала как тап).
- Если движение было, но меньше порога — тоже подавить `click` (это была протяжка, не тап).
- Вертикальное движение по полоске ничего не делает.
- Свайп влево (`dx < 0`) — следующий лист, вправо — предыдущий.
- После переключения: `list.scrollTop = 0`, лёгкая вибрация через `window.__hapticLight`, если доступна.
- Аудит: `Audit.log({ type: 'UI', details: { action: 'sheetSwitch', sheet: key ?? 'main' } })`.

### 7.4. Клавиатура

- `ArrowLeft` / `ArrowRight` — предыдущий / следующий лист.
- Игнорировать: `INPUT`, `TEXTAREA`, `SELECT`, `contenteditable`, модификаторы (`Alt/Ctrl/Meta/Shift`).
- Игнорировать, если открыт монитор или меню ветки.
- Если листов меньше двух — ничего не делать.
- `preventDefault`, чтобы браузер не скроллил.

## 8. Активный лист

- `state.activeSheet`: `null` (главный) или ключ ветки.
- Хранится **по ключу**, не по индексу: изменение состава листов не должно уводить на чужой лист.
- Только в памяти. После перезагрузки — главный. В `localStorage`/URL/БД не пишется.
- На каждом `render()`: `state.activeSheet = resolveActiveSheet(sheets, state.activeSheet)`.
- Переключение не пишет в БД и не меняет заметки.
- Смена листа сбрасывает скролл списка вверх.

## 9. Добавление, смена ветки, исчезновение листа

### 9.1. Добавление заметки

После `addNote` → `loadNotes()` → `render()`:

1. Вычислить лист заметки: если её ветка в `overflow` — лист ветки, иначе главный.
2. Если это **не** активный лист — показать toast с действием:
   - главный: `Заметка на главном`;
   - ветка: `Заметка на листе «Работа»`;
   - кнопка `Открыть`, время 4 с.
3. Автоперехода нет. Пользователь сам решает, идти ли туда.

Toast расширяется обратно совместимо:

```js
toast(msg, { actionLabel = null, onAction = null, duration = 2500 } = {})
```

- Без `actionLabel` — прежнее поведение (текст, 2.5 с, `pointer-events: none`).
- С действием — `pointer-events: auto`, кнопка `.toast-action`, тап по кнопке переключает лист и скрывает toast.
- Существующие вызовы `toast('...')` не меняются.

### 9.2. Смена ветки через меню

После debounce-коммита `Corrections` и `render()` — то же правило, что при добавлении. Если заметка ушла на другой лист, вместо/вместе с текущим `ветка → …` показать toast с `Открыть`. Если заметка осталась на активном листе — оставить текущий toast без действия.

### 9.3. Исчезновение активного листа

Лист исчезает, когда активных заметок ветки становится ≤ 5 (выполнили, удалили, сменили ветку). Правило:

1. Пересчитать листы.
2. Если `state.activeSheet` больше не существует — переключиться на главный и отрисовать его.
3. Показать toast: `Лист «Работа» свернулся — заметки снова на главном` (3 с).
4. Никаких слияний/переносов в БД: просто снят фильтр.

Тост показывается только при мутации (toggle/delete/смена ветки/restore), не при фоновом тике и не в полночь — там уже есть «Новый лист».

### 9.4. Восстановление из корзины

Если восстановление создаёт новый лист ветки (переход 5 → 6 активных) и заметка оказывается не на активном листе — тот же toast с `Открыть`. Если остаётся на активном — без тоста.

## 10. Пустые состояния

- `sheet.length === 0 && overdue.length === 0`:
  - главный, листов больше одного, есть активные заметки на других листах:
    `На главном пусто.` / `Всё разложено по листам — полистай внизу.`
  - лист ветки (защитный случай):
    `На этом листе пусто.` / `Заметки вернутся, когда ветка снова разрастётся.`
  - иначе — существующее `Жду задачи. Лист открыт, места много.`
- Если есть только выполненные сегодня — приветствие не показывать, показывать «Сделано сегодня».
- Корзина рендерится ниже пустого состояния, как сейчас, но отфильтрована по листу.

## 11. Доступность

- `nav aria-label="Листы"`.
- Точки — обычные `button` с `aria-label="Работа, заметок: 7"`; активная — `aria-current="page"`.

- Видимый `:focus-visible` у точек и стрелок.
- Полоска 44 px, точка 24×24 px.
- Контраст: активная точка — цвет ветки + граница `var(--ink)`; неактивная — контур `var(--muted)`.
- `prefers-reduced-motion` — без анимаций (их и так нет).
- При одном листе полоска `hidden` и не мешает скринридеру.

## 15. Критерии приёмки

1. При ≤ 5 активных заметках в каждой ветке полоски нет, главный лист выглядит как раньше.
2. 6-я активная заметка в «работа» создаёт лист «Работа · 6»; все заметки «работа» исчезают с главного.
3. Точки, стрелки, свайп по полоске и ←/→ переключают листы; на краях — кламп.
4. Свайп влево по заметке по-прежнему выполняет; вправо/диагональ/вертикаль — ничего; long-press 300 мс — меню; ЛКМ — выполнено; ПКМ — меню; протяжка мышью — ничего.
5. На листе ветки: только её активные, её «Сделано сегодня», её корзина, её «Просрочено»; дайджеста нет.
6. На главном: глобальное «Просрочено» (включая разросшиеся ветки), дайджест, нет заметок разросшихся веток в активных/выполненных/корзине.
7. Довели ветку до 5 активных — лист исчез, активный лист вернулся на главный, toast объяснил; данные не потеряны.
8. Добавили заметку на неактивный лист — toast с «Открыть», без автопрыжка; кнопка переключает.
9. Перезагрузка → главный лист; активный лист не персистится.
10. Офлайн работает после SW v4; все ассеты в кэше.
11. 320 px: полоска помещается, заголовок с ellipsis, горизонтального скролла нет.
12. `npm test` зелёный; `node --check`; DOM-гейт; real-touch 390×844.
13. Нет миграции БД, нет изменений формата экспорта, нет потери данных.

## 16. Предлагаемые решения (на утверждение)

1. **Порядок листов** — фиксированный `BRANCH_KEYS`, а не по количеству. Стабильно: листы не перескакивают, когда счётчики меняются.
2. **Исчезновение активного листа** — сразу вернуться на главный + toast. Это прямое следствие правила «при ≤ 5 лист исчезает»; toast смягчает переход.
3. **Заголовок главного** — `Все · N` (коротко для 320 px). Альтернатива — `Главная · N`.
4. **Toast при добавлении** — с кнопкой `Открыть` (как в решении «toast с переходом»). Без кнопки текст быстро исчезает и не даёт перейти.
5. **Пустое состояние главного** — `На главном пусто` + `Всё разложено по листам — полистай внизу.` Вместо «Жду задачи», чтобы не врать, когда заметки есть, но на других листах.
6. **SHT-005** — делать в M8 или отложить до отдельного релиза extension. Рекомендация: отложить, сначала телефон/APK.

## Приложение A. Почему не свайп по списку

Свайп влево по заметке уже занят выполнением (UX-001). Если добавить листание по списку, придётся либо отбирать у пользователя выполнение, либо вводить неоднозначный арбитраж по скорости/длине. Нижняя полоска — отдельная поверхность с собственным `touch-action: none`, поэтому конфликт исчезает полностью. Это и есть закрытие TD-DEV-22.

## Приложение B. Почему не копия данных

Лист — это `filterBySheet(notes, key, overflow)` на каждом рендере. Нет второй таблицы, нет `sheetId` у заметки, нет синхронизации. Поэтому:

- добавление/выполнение/удаление сразу видны на всех листах, где заметка должна быть;
- исчезновение листа не требует переноса;
- экспорт/импорт и обучение не знают о листах;
- сбой рендера не может потерять данные.
