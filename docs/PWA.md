# PWA на Android

Цель: установить «Живой блокнот» на домашний экран Android как приложение, без APK и стора. Позже — отдельная Capacitor-оболочка (APK), если понадобятся нативные функции.

## 1. Что входит в PWA-срез

- `www/manifest.webmanifest`:
  - `name`, `short_name`, `start_url: "./"`, `scope: "./"`, `display: "standalone"`,
  - `background_color`, `theme_color`, `orientation: "portrait"`,
  - иконки 192×192, 512×512, maskable 512×512.
- `www/sw.js`:
  - кэш `livenotepad-v3` (app shell: `index.html`, `js/*`, manifest, иконки);
  - ASSETS: `./js/entities.js`, `./js/capacitor.js` и все остальные модули;
  - network-first для навигации и same-origin GET;
  - versioned cache, удаление старых кэшей по префиксу `livenotepad-`;
  - `skipWaiting` + `clients.claim`.
- `index.html`: `link rel="manifest"`, `apple-touch-icon`, регистрация SW (`updateViaCache: 'none'`).
- `test/pwa.test.js`: manifest-поля, наличие иконок, базовые инварианты SW.
- Метрика гейта: `navigator.serviceWorker.ready` + offline reload.

## 2. Как установить на Android

Полное пошаговое руководство со скриншот-логикой и разбором проблем: [docs/GETTING_STARTED.md](GETTING_STARTED.md). Здесь — сжатая версия.

### Шаги

1. Открыть **https://dropingcat.github.io/livenotepad/** в **Google Chrome** (не во встроенном браузере мессенджера).
2. Меню **⋮** → **«Установить приложение»** (или **«Добавить на главный экран»**, если первого пункта нет).
3. В диалоге «Живой блокнот» → **«Установить»**.
4. Запустить с иконки «Блокнот»: standalone-окно, без адресной строки.
5. Проверить офлайн: включить **авиарежим**, закрыть приложение (смахнуть из недавних) и открыть снова — лист должен открыться, данные на месте.

### Что именно даёт установка

| | Вкладка Chrome | Установленное приложение |
|---|---|---|
| Окно | внутри браузера, с адресной строкой | отдельное, без строки |
| Иконка на экране | нет | «Блокнот» |
| Офлайн | пока вкладка жива | самостоятельное окно, надёжнее |
| Данные | та же IndexedDB (тот же origin) | та же IndexedDB |

Обе версии — одно приложение и одни данные. Разница — только оболочка запуска.

### Признаки, по которым Chrome предлагает установку

- манифест с `start_url`/`scope`/`display: standalone` и иконками 192/512/maskable;
- service worker с fetch-обработчиком;
- HTTPS (или `localhost`).

Наш адрес — HTTPS, всё три условия выполнены.

### Если пункта «Установить приложение» нет

1. Открыто не в Chrome (встроенные браузеры мессенджеров установку не предлагают).
2. Открыт LAN-адрес `http://192.168.1.100:8080` — не secure context, установка недоступна.
3. Chrome ещё не «созрел» — обновите страницу и подождите пару секунд.
4. Есть только «Добавить на главный экран» — используйте его.
5. Ничего нет — откройте во вкладке (работает), соберите аудит и пришлите на разбор.

LAN-вариант `http://192.168.1.100:8080` — **не secure context**: `crypto.subtle`/`randomUUID` отсутствуют, install PWA и service worker недоступны. Установка — только с HTTPS (Pages) или `localhost` (тоже secure context). LAN — для отладки и UI-проверок; IndexedDB у LAN и Pages — разные origin: данные не переносятся автоматически.

## 3. Ограничения (осознанные)

- Фоновых уведомлений о сроках нет — решение пользователя: достаточно бейджа/списка «Просрочено» при открытии.
- Синхронизации между устройствами нет — локальные данные + экспорт/импорт файлами.
- Нет нативных share/haptics/splash/deep links — это Capacitor-APK (позже), не PWA.
- Аудит и заметки хранятся в IndexedDB телефона; выгрузка — вручную через «Скачать аудит»/экспорт.

## 4. Обновления

Pages обслуживает ветку `gh-pages` (содержимое `www/`). Обновление: `git push origin main` + `git subtree push --prefix www origin gh-pages`. SW использует network-first: онлайн-версия обновляется, офлайн — из кэша. После обновления может понадобиться один перезапуск приложения (SW активируется и забирает управление). Кэш именуется с префиксом `livenotepad-`; `activate` удаляет только свои кэши, чтобы не трогать другие проекты на общем origin `dropingcat.github.io`.

## 5. Проверка

- `npm test` — manifest/иконки/SW-инварианты.
- `node --check www/sw.js`.
- Браузерный гейт: SW `ready`, offline reload, IndexedDB на месте, `consoleErrors` пустые, `appHash`/`stepCount/passCount` в артефакте.
- На телефоне: установка, открытие с иконки, создание заметки, аудит → «Скачать аудит», авиарежим → перезапуск.
